# P8-E1 对齐修复听感包（4×5）

本包只从已有 30 s WAV 读取并裁剪，源文件、checkpoint 和旧试听包均未修改。每个样本包含 `noisy / clean / Y_pre / Router-off / Router` 五段，裁剪范围是目标 0.5 s 窗口前后各 0.75 s（共 2.0 s）；文件名中的时间是目标窗口，不是上下文起点。

## 选择规则

在中央 12 s 可用范围 `[9, 21] s` 内，排除旧 `p8_counterexample_listening_pack_20261020` 的四个窗口；从候选表按 noisy-clean 局部波形相关及 clean-aware 局部 SNR 排序，优先选择较高局部证据且目标窗便于连续听辨的窗口。由于剩余候选没有达到 −10 dB 的窗口，实际四段为 −10.86、−11.38、−14.28、−17.12 dB；这些数值用于透明记录，不能当作部署时可观测信号。

## 时间/语义对齐诊断

`metrics.json` 和 `alignment_scan.json` 对每个源文件检查了采样率、样本数、SHA-256，并在 ±100 ms 范围扫描与 clean 的最大相关。五个 arm 的最佳滞后均为 **0 样本（0 ms）**，所有源均为 16 kHz、480000 样本（30 s）。因此本包未发现由裁剪时间偏移或文件错配导致的差异。

noisy 的零滞后相关仍可很低（约 0.10–0.46），这是低 SNR 噪声掩蔽下的内容证据弱；不能据此断言文件错位。若听感中 noisy 与 clean 词句不一致，而五个 arm 同步为 0 ms，应记录为“噪声下辨识失败/局部证据不足”的候选解释；若 Y_pre、Router-off 或 Router 与 clean 内容仍不一致，则另行记录“模型语义偏离”，不要写成“文件错位”。

音频索引见 `listening.html`；逐条源路径、哈希、局部指标和对齐扫描见 `metrics.json`。
